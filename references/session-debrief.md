# Session Debrief — 成绩单 + 错题本

每次面试模式结束（用户说「结束」「先到这」「总结一下」，或 mock 自然收尾）**必须**产出：

1. 对话里的人话成绩单 + 错题摘要  
2. 写入练习区：`scorecard.md`（追加本场）+ `错题本.md`（追加条目）+ 更新 `session-state.md`

进行中仍隐藏刷分标签；**只在收尾**亮成绩。

---

## 成绩单维度（每项 1–5，附一句理由）

| 维度 | 看什么 |
|------|--------|
| 产品叙事 | 问题、用户、方案、取舍是否闭环 |
| 系统理解 | 主链路、Agent vs 流程、关键对象关系 |
| 证据意识 | 能否指到代码/数据，而非「应该」 |
| 简历对齐 | 简历句子能否被项目证明；有无乱抬角色 |
| 失败与边界 | 取消、重试、空结果、无数据时是否诚实 |
| 口述抗压 | 被打断、追问后是否仍结构化 |

另给 **综合印象**：通过 / 边缘通过 / 未通过（面试点评口吻，非恐吓）。

## 出题质量（避免简单片面）

收尾前自检本场是否犯了这些忌讳；若犯了，下次开场先补一层：

| 忌讳 | 改成 |
|------|------|
| 只问「X 是什么」 | 问「为什么要 X 而不是 Y」「谁触发、失败怎么办」 |
| 只停在功能列表 | 逼因果链：输入→决策→工具→落盘→用户可见 |
| 只问技术或只问产品 | 每 2–3 题交叉：产品取舍 ↔ 实现约束；简历句 ↔ 代码证据 |
| 答完就换大题 | 同一点至少：主问 → 收窄/要证据 → 反事实或失败 之一 |
| 简历与项目两张皮 | 至少 2 次显式引用简历原句再往下扎 |

详见 [question-framework.md](question-framework.md)「深度追问协议」。
