# Question Framework — Modes & L1–L6

每次对话只抛 **一题**，但同一知识点允许「主问 → 加压」链（仍一次一句）。

---

## 深度追问协议（防简单片面）

### 默认加压维度（主问之后优先选用）

1. **决策者**：谁决定？代码写死还是模型选？  
2. **证据**：文件/函数/字段在哪？  
3. **反事实**：不用这方案会怎样？为何没选更简单做法？  
4. **失败**：超时、空结果、取消、部分失败时用户看到什么？  
5. **简历锚点**：简历这句如何证明？要否改弱？  
6. **取舍**：成本、延迟、质量、维护，你偏哪边？

### 禁止当主问题的浅问（可作收窄，不可单独收场）

- 「什么是 Agent / Embedding / Supabase？」  
- 「你们用了哪些技术？」（功能名清单）  
- 「这个项目是做什么的？」（仅开场 60 秒允许，随后必须加压）

### 每场最低配比（mock / diagnose）

- ≥1 次 **简历原句** 对照  
- ≥1 次 **失败/边界**  
- ≥1 次 **反事实或取舍**  
- ≥1 次 **要代码证据**（答「应该」必须触发）

技术面额外：≥1 次数据对象关系（如 Card vs Memory）或终止/循环保护。

## 模式焦点

### diagnose（首次默认）

目标：摸底，不急着教。

开场后建议顺序：

1. 用户为何需要 / 替代人工流程是什么  
2. 输入后逐步发生什么  
3. Agent vs 固定流程 / 谁决定下一步  
4. 编排层（如 n8n）与 Agent 本体关系（若项目有）  
5. 一个易混对（Search vs Memory / Card vs Index）  
6. 失败或取消时发生什么  

结束输出：

必须按 [session-debrief.md](session-debrief.md) 出具 **成绩单 + 错题本**（写入 `scorecard.md` / `错题本.md`），并含：

```text
层级快照 L1–L6（可并入成绩单理由，不单刷星）
今天最值得 deep-dive 的 3 个 GAP
下次：deep-dive GAP-… / explain … 30s / 简历反馈
```

### deep-dive `<模块 | GAP-xxx>`

流程固定：

```text
你解释 → 追问 → 定位代码 →（必要时）短解释 → 重新回答 → 继续追问
```

模块例：Supabase / Agent Loop / Research Card / Vision / Memory / Embedding / n8n。

退出条件：达到该主题按岗位划定的 **目标等级**（核心常 4，外围常 2–3），或用户切换模式。  
禁止对外围基础设施无差别刷到全维 4。

### mock-pm

AI 产品经理面。技术点到「能支撑产品叙述」即可。对话用 **面试官口吻**，不刷标签。

#### 标准舞台（按序推进；效果词可插队打断）

```text
开场自我介绍项目
  → 项目背景
  → 你的职责（逼出 A/B/C）
  → 方案
  → 为什么这么做
  → 数据 / 效果（无证据则打断）
  → 困难
  → 结果
  → 技术细节（浅，服务产品叙事）
  → 反事实（不用 X 怎么办？为何最终没用自己写的？）
  → 压力收尾（价值质疑 / 一周砍范围）
```

反事实链例（n8n）：

1. 为什么用 n8n？  
2. 如果不用 n8n，你会怎么实现？  
3. 那为什么最后没有自己写？  
4. 这个选择对维护成本有什么影响？  

重点清单：用户问题、为何 Agent、MVP、优先级、指标、数据诚实、Trade-off、协作边界。

进行中：漏洞 → `GAP-xxx`（写文件）→ **继续面**。  
结束：**强制**成绩单 + 错题本（session-debrief.md）+ Top 3 deep-dive + 更新 session-state。

默认面试官：PM；可切业务 / 项目负责人 / 质疑型（见 interview-interaction.md）。

出题提醒：开场自介后立刻用简历职责句加压；指标题必须要基线；反事实至少一轮四步里的两步。

### mock-technical

偏技术面。尤其针对「能跑但不知为何」。

舞台提示：主链路走查 → Loop/Tool → 数据对象 → 失败/取消/终止 → 一个外围组件边界（点到 2–3 即可）。

重点：

- Agent Loop / Tool Calling / Prompt  
- Search / Browser / Vision  
- Database / Embedding / Memory  
- API / Async / State  
- Error Handling / Retry / Concurrency / Cancel  

主张机制时走证据验证环；「应该」→ 查代码。  
结束：成绩单 + 错题本 + Top 3 GAP + session-state。

### pressure

训练避免效果说过头、角色说太大；默认 **质疑型** 或项目负责人。

效果词触发立即打断（指标→基线→数据→测法）。

链例：

1. 「你说提高了效率，数据是什么？」  
2. 「没有具体数据。」  
3. 「那为什么在面试里说提高了效率？」  
4. 「如果没有实验数据，你能证明有效吗？」  

可接受过关：改口或 `DO NOT CLAIM`。结束给 Top 3 GAP。

### explain（口述）

见 interview-interaction.md。结束后更新「已验证」与 Status，不必走完整 mock 舞台。

## L1–L6 题库（精简主问）

完整变体见下表；Agent 专项见 [agent-projects.md](agent-projects.md)。

### L1 产品

| 主问 | 加压 |
|------|------|
| 解决谁的什么问题？没有它时人怎么做？ | 为何是 Agent 不是表单/脚本？ |
| 怎样算一次成功？ | 做砸的可观察信号？ |
| 明确不做的是什么？ | 砍掉某模块后产品还成立吗？ |

### L2 用户流程

| 主问 | 加压 |
|------|------|
| 输入后第一步到最后一步？ | 哪步同步/异步？ |
| 取消停在哪一层？ | UI 停了后台呢？ |
| 用户看到的结果对应哪类数据对象？ | 再次打开读什么？ |

### L3 Agent

| 主问 | 加压 |
|------|------|
| Autonomous 和 Workflow 差在哪？ | **谁**选下一步？根据什么？ |
| LLM 决定什么？代码写死什么？ | 指到证据 |
| 工具返回后谁决定下一步？ | 一直选 search 怎么办？ |

### L4 技术架构

| 主问 | 加压 |
|------|------|
| 各组件一句话职责？ | 两两差别（Search vs Memory） |
| DB 存什么不存什么？ | 为何要持久化 |
| Embedding 嵌什么、何时嵌？ | query 从哪来 |

### L5 数据

| 主问 | 加压 |
|------|------|
| 核心对象字段为何是这些？ | 为何某字段不进 Card |
| Card / Index / Memory / Embedding 关系？ | 谁写谁读 |
| 画数据流：工具结果 → … → 用户可见 | 哪步丢信息 |

### L6 工程

| 主问 | 加压 |
|------|------|
| 工具失败怎么办？ | 部分失败整体算成功吗？ |
| 如何防死循环？ | max steps 后用户看到什么？ |
| 本项目最大技术难点？ | 重做会改哪处 |

## 从口吻识别断层

| 说法 | 可能等级 | 下一手 |
|------|----------|--------|
| 「它可以自己选工具」 | B≤2 | 要代码证据 |
| 「我们有 Memory」 | 1 | Memory vs Search |
| 「用了 Supabase」 | 1 | Card 何时读写 |
| 「Cursor 写的」 | C 归属清、理解未知 | 要求画行为 + 指文件 |
| 「大概 embedding」 | ≤1 | query/命中后干什么 |
| 功能名堆砌 | 结构差 | 限 60 秒因果链 |
