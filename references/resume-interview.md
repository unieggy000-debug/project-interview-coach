# Resume × Project Interview

面试同时吃两份材料：**简历表述** + **项目代码事实**。目标不只是讲清项目，还要标出简历哪里该改。

## 开场必收（缺一不可）

1. **项目**：当前已打开的项目文件夹，或用户发来的本地路径 / Git 链接（有本地仓优先本地）。  
2. **简历**：文件（拖入）、本地路径，或粘贴正文。保存到练习区 `resume.md`（或注明原文件路径）。

缺哪个就**只问缺的那个**，用大白话，不要说「Workspace Root」。

## 提问方式

每隔若干轮，插入 **简历锚点题**：

- 「你简历上写……，对应项目里哪一步？」  
- 「这里写的 Owner / 主导，代码或文档能证明到哪一层？」  
- 「指标有没有基线？简历要不要改成更弱但诚实的说法？」  

仍遵守：不直接给标准答案；机制题要代码证据。

## 练习区产物

| 文件 | 内容 |
|------|------|
| `resume.md` | 用户简历原文或摘录 |
| `resume-feedback.md` | 可改点：夸大 / 含糊 / 缺证据 / 建议改写（给方向不代写整份简历，除非用户要求） |

每条反馈带：简历原句 → 问题类型 → 建议改法（一句）→ 相关项目证据或 UNKNOWN。

## 与 Interview Status 的关系

简历里的主张同样打 Status：

- SAFE：代码+理解都站得住，可保留  
- QUALIFIED：可写，但要加限定（协助实现 / 模块范围）  
- FRAGILE / DO NOT CLAIM：建议删或改弱  

## 禁止

- 未要到简历就开始「完整面试」假装已经对照过简历  
- 用简历审计 skill 去开盒或做人身攻击；只谈表述与证据
