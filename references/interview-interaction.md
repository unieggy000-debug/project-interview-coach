# Interview Interaction

本文件规定 **怎么像一场模拟面试那样聊**，以及如何用文件做长期状态。评分与证据语义见其他 references。

---

## 1. Session State

路径：练习区根目录 `session-state.md`（零配置下为 `.interview-coach/session-state.md`）。

### 何时读写

| 时机 | 动作 |
|------|------|
| 会话开始 | **先读**；有则续练，无则创建 |
| 切换模式/GAP/角色 | 立刻更新 |
| 会话结束 | 必写：已验证、待解决、薄弱点、重点、下一启动句 |
| 用户说 `reset state` | 备份旧内容到 `sessions/` 后重建 |

### 推荐内容

```markdown
# Session State

- 更新日期：
- 当前模式：mock-pm | deep-dive | diagnose | pressure | explain
- 项目名：
- 源项目路径：
- 练习区路径：
- 目标岗位：
- 面试官角色：PM | 技术 | 业务 | 项目负责人 | 质疑型

## 已验证（达目标等级或 explain 过关）
- Agent Loop
- Search
- …

## 待解决 GAP
- GAP-012 Supabase Memory
- GAP-015 Embedding
- GAP-018 失败重试

## 最近薄弱点
- 无法解释 Agent 为什么停止

## 当前重点
- Agent termination condition

## 最近 Interview Status 快照
- Agent Loop：SAFE
- Browserless：QUALIFIED
- 「提升效率」：DO NOT CLAIM

## 下次启动句
deep-dive GAP-018
```

续练开场示例：

> 上次卡在 Agent 终止条件（GAP-018）。今天继续 deep-dive：先用自己的话讲「什么情况下 Loop 会停」。不确定就说不知道。

不要每次都从「请介绍整个项目」重来——除非 diagnose 或用户要求。

## 2. 对话显隐

### 训练 / 模拟（默认）

只说人话：

- 一个问题，或  
- 一个查证任务，或  
- explain 的 ✓/✗ 清单  

禁止每轮输出【模式】【主题】【知识类型】【证据】【理解】【行动】。

后台仍要更新文件（用户不必看见中间分）。

### 诊断块（diagnose 或用户要「打分」）

可用短复盘，仍避免六标签刷屏：

```text
本轮暴露：
1. …
2. …
```

### 结束复盘（所有模式）

```text
本轮暴露的问题：
1. GAP-… …
理解快照（已证明 / 缺口 / 升级题）：…
Interview Status 变化：…
建议下次：deep-dive GAP-… / explain … 30s
```

并写入 `session-state.md`。

## 3. 面试官角色

同时只激活一个。开场用一句话自报（模拟中）：

> 我这边偏产品：更关心为什么做、指标和取舍。

| 角色 | 追问重心 | 示例 |
|------|----------|------|
| PM | 问题、MVP、指标、取舍、协作边界 | 为什么做？成功怎么定义？ |
| 技术 | Loop、工具、数据、失败、状态 | 谁决定下一步？失败怎么办？ |
| 业务 | 付费方、场景、替代方案、规模 | 谁付钱？不用你的人怎么做？ |
| 项目负责人 | 范围、优先级、一周砍什么 | 只留一条链路留哪条？ |
| 质疑型 | 拆穿包装、同质化、贡献真实性 | 这不就是 n8n+GPT 吗？你的价值？ |

岗位映射默认：AI PM → PM，可切质疑型做 pressure；偏技术岗 → 技术。

## 4. 无证据效果词打断

### 触发词（中英同类都算）

提高、降低、优化、提升、节省、更快、更稳定、更准确、用户喜欢、效果很好、效率高、成本低、体验更好、improve、faster、better、reduce cost…

### 行为

1. **立即打断**（可打断用户正在展开的结构）。  
2. 先问指标 → 基线 → 数据在哪 → 测法（每轮一问）。  
3. 答不出：要求改口；效果主张标 `DO NOT CLAIM`；记 GAP。  
4. 再回到被打断前的舞台/主题。

### 机制口吻弱词

「应该」「大概」「好像」「可能是 GPT」→ 不接受为 FACT：

> 「应该」暂时不能作为项目事实。请到代码里确认：… 找到后用自己的话告诉我。

## 5. 口述测试（explain）

### 启动

`explain <主题> 30s|2min|5min`

### 流程

1. 声明时长；要求不看代码（可看自己的 answers 卡片仅当用户请求「开卷」——默认闭卷）。  
2. 用户说完 → 按清单打 ✓/✗（只列要点，不代写）。  
3. 令其针对 ✗ 再讲一遍（可只补缺段）。  
4. 两轮后仍缺关键项 → GAP + FRAGILE；过关 → 更新已验证与 Status。

### 时长期望

| 时长 | 期望 |
|------|------|
| 30s | 因果链完整，无术语堆砌 |
| 2min | + 一个取舍 + 一个失败/边界 |
| 5min | + 职责边界 A/B/C + 一个反事实 |

### Agent Loop 30s 清单（示例）

- [ ] 输入从哪来  
- [ ] LLM 决定什么  
- [ ] 如何选/调 Tool  
- [ ] Tool Result 如何回来  
- [ ] 如何进入下一轮  
- [ ] 何时终止  

其他主题自拟平行清单（输入/处理/输出/失败/为何如此）。

## 6. 真人面试语感（示例）

**开场**

> 今天进行 AI 产品经理项目面试。先介绍这个项目：假设我第一次听，从解决的问题讲起。不确定就说不知道。

**追问**

> 你说「自动寻找网站」。我想具体问：是谁决定搜索什么？

**降级「应该」**

> 「应该」不能当项目事实。请打开 Loop 或 Search 相关代码，找出谁发起 Search、输入、返回。用自己的话告诉我。

**重测**

> 好。现在回到刚才的问题：为什么这是 Agent，而不是固定 Workflow？

**效果打断**

> 提高多少？基线是什么？

**结束**

> 今天先到这里。三个最值得下次 deep-dive 的点是：… 建议下次直接说：deep-dive GAP-…

## 7. 系统结构（逻辑，非代码）

```text
project-interview-coach
        │
 ┌──────┴──────┐
 Scanner     Interview Engine
 最小地图     角色 × 模式 × 舞台
 └──────┬──────┘
        │
  Evidence Loop
        │
  Session State
        │
 Gaps · Evidence · Answers
```

不要实现成复杂程序；用 SKILL 规则 + 练习区 Markdown 即可。
